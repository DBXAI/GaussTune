# 轻量阶段化 TPS 桥接设计（2026-11-14）

## 回退基线

修改前版本 `8a82027` 已推送并标记 `jmt-before-phase-bridge-20261114`。
保留原冻结预测和原始测量，不以新校准覆盖旧标签。

## 本轮三条并行对照口径

1. **历史 TP 校准＋新鲜盲计划**：原方法的本轮对照。
2. **新 TP 校准＋新鲜盲计划**：只修正同机 CPU 记账、刷新 TP 基线；
   AP 仍是全查询平均需求，不能提前宣称波动已解决。
3. **短期自适应 CPU 条件预测**：在目标15秒窗口之前观测4秒的明确所属 AP 线程；
   只用这段 AP CPU 和独立 TP-only 校准，预测后续窗口。
   不把目标窗口的 TPS/CPU/IO 放进预测；不是纯计划冷启动模型。

本轮不训练 QueryID/阶段专属系数，不重新搜索 WM/SB，不改变创新三最小spill目标。

## TP 校准

- 同机数据库 TP 后端和真正 Sysbench 工作线程的 CPU 分开记录，再合并为总 CPU 服务需求。
- 校准与验证严格区分 TP128 和真实预热128＋首事件门控16；不以平144代替。
- 每个原样 SB 点：repeat1提供参数，repeat2只作留出核对，不选择二者中更有利的一次。
- 只服务实际测过的 SB/拓扑组合；不因有5.25GiB观测就外推8GiB或宣称最优。
- 容量检查和CPU窗口100ms门限保持，不靠缩放错位计数修正。

## 轻量阶段信息

- 从明确所属 AP 的 `/proc/.../schedstat`、线程身份和 `/proc/.../io` 读取两个端点。
- 4秒是观测等待，不是计算时间；每次预测计算与端点读取分别记录。
- 使用当前 AP CPU核数时，其 IO 阻塞已经反映在 CPU/wall 比中，
  **不能再拿全查询逻辑扫描量把这份 CPU 二次压低**。
- 当前版本用现有有界CPU队列求解；AP数量线性输入，固定16核的小常数计算。
  无全数据扫描、逐页在线追踪、神经网络或查询专属拟合。
- Task IO 字节是提交/记账诊断，不是设备完成数；
  不把 syscalls当作物理IOPS，不把未知TP物理IO所有权填0。

## 仍未解决的界线

第三条当前是“额外 AP 物理IO等待未建模”的 CPU 条件场景；
IO诊断用于定位阶段变化，不等于物理IO等待模型已通过验收。
真实带宽、请求节奏、后台写回以及TP所有权仍须分开验证。

纯计划冷启动如何把算子图转换成随执行进度变化的资源段，
以及阶段突变时4秒观测是否能代表后续15秒，也仍需独立检验。
本轮真实五阶段全程保留这两种口径，不能把自适应预测成绩冒充冷启动成绩。

## 可审计性

- 开跑前冻结两条静态预测、TP训练/留出划分、源码与SQL/WM绑定。
- 每个自适应预测写独立 `PREWINDOW_PREDICTION.json`，保存时间必须早于目标内核窗口。
- 离线按输入重算并逐个核对预测，不仅复算MAPE。
- 事后以目标 AP CPU 替换的实验单独标记为诊断，不算留出预测或训练样本。
- 原生配额不扩大，不重启，窗口结束仅取消本实验AP并恢复SB/配置。

## 已定位的采集协议差异

首轮 AP 预观测在计数观察器挂载之前，计分窗口则在挂载之后。
第二轮把钩子移到观察器创建/明确所属TP后端登记之后：
预观测和目标窗口都挂载同一个观察器，预观测时计数窗口尚未启用。
保存 `observer_attached_during_AP_probe` 与 `commit_count_window_disarmed_during_probe`
并在离线审计中核对。不把计数器开销视为已量化或已校正。

两轮属于不同连续轨迹，不能仅凭前后误差变化断言观测开销的因果效应；
修复的确定内容是采集条件一致，不是某个TPS提升百分比。

## 不允许的推广

4秒预观测的CPU即使完全正确，也不保证随后15秒没有算子/IO阶段切换。
独立TP-only校准精度也不保证AP竞争下每事务CPU服务成本不变。
新模式必须以各自真实留出结果验收，失败实验保留；
没有通过端到端验证前，不作为默认推荐模式，不以新的基线抵消另一个模型的错误。
