# AP → SB 压力预测：开始测试前的设计快照

日期：2026-11-13。此文件保存已讨论的方案，不代表新模型已经实现或通过实测。

## 回退基线

当前四项创新源码及 `MIXED_SB_COMPETITION_CURRENT.md` 是回退基线：

- 第一步的 4 GiB 是 TP-only miss 曲线提示，不能用作混合负载硬上界。
- 第三步已放开 6/8 GiB，五阶段 65 个冻结 spill 点独立核对一致。
- 有界混合事件回放已实现；真实混合 profile 尚未接入第四步排名。
- 734 项回归通过，未宣称新的 SB 最优或物理安全配置。

## 新增预测职责

创新二在 query × WM spill 输出之外，追加轻量 AP 缓存压力描述：

1. 区分 bulk-read ring、一般池表/索引访问、私有执行内存和 spill 文件。
2. 用计划、关系页数、算子调用次数、访问唯一性和存储策略估计名义驻留。
3. 同一物理关系需要去重；重复调用不等于反复新增独占缓存。
4. 扫描量不等于同时占用量；扫描速率、ring 回退和替换路径影响污染。
5. 用短窗口通用校准补充一般池装入与 TP miss 损失，不能按 query 编号拟合系数。
6. 输出低/中/高压力情景、缺失输入和适用域，不能将情景范围称为统计置信区间。

候选轻量桥接：

```
TP_effective_SB ≈ shared_SB - AP_equivalent_cache_pressure
mixed_TP_miss ≈ TP_only_miss_curve(TP_effective_SB)
```

这只是待检验的代理模型。名义 AP 驻留量不一定等于 TP 的等效容量损失。
不能把 TP-only 缓存曲线简单平移后就自动认证混合 TPS。

## 四项创新的职责不变

- 创新一：TP-only 基础缓存需求，以及混合回放/短窗口验证。
- 创新二：算子 spill 与 AP 缓存压力特征，不输出拍脑袋的固定 AP GiB 补偿。
- 创新三：每个 SB 的剩余 AP 预算下最小化总 spill。
- 创新四：比较 TP 缓存收益和 AP spill/CPU/IO 代价，保留不确定性与证据门禁。

SB 是共享池，不是真的为 TP 划独占内存。SB 增加会压缩 AP 规划余量，不能只加不减。

## 第一轮测试

- 先对现有 Q2/Q9/Q13/Q18/Q21 冻结计划提取名义压力，禁止续期旧 AP 统计。
- 覆盖 ring 复用、重复访问/物理关系去重、未知算子、索引与顺序扫描差异、
  WM/计划变化、ring 规则使用启动池而非在线目标池等单元测试。
- 能安全执行时，用受限只读查询验证缓存路径/页数；不重启、不缩放生产 SB、
  不清空缓存、不全表跑巨大事实表、不擅自启用有风险的追踪/内存配置。
- 无法识别的真实 ring 回退率/扫描速率保持 unknown，不用任意系数补成 6/8 GiB。
- 效果测试与实现测试分开，记录失败案例，不把“运行成功”当准确率验收。
