## 1. 真正完成的验证

- 独立 TP128：SB=2/4/6/8GiB，各两次；第一次校准、第二次留出。
- TP-only 留出 MAPE：**0.3687%**，并不保证稍后混合批次的基线不漂移。
- 原始 SF85 q9/q13/q18/q21，LOW/HIGH 两档 WM、4 个 SB、两个反序重复：
  **16 个独立 AP 重启目标窗口 + 8 个 AP-free TP 控制窗**。
- 每个目标窗 20 秒，AP 开始后约 17.90–22.05 秒进入测量。
- 当前 TP 控制点在未来 AP 开始前冻结，其年龄为 **1.49–72.11 秒**；
  独立校准点年龄为 490.55–1758.76 秒。控制点是这两条消融的校准输入，
  不能同时说它们是这些预测的独立 TP 留出集。

近邻控制点带来的改善也不是 CPU 排队公式的功劳。

## 4. 中间量与卡点

- AP 实际占核 **0.427–1.214 核**；固定全查询平均占核不是当前阶段占核。
- 原单向 AP 占核 MAE=0.267 核；反馈后约 0.243 核，仍不够准确。
- AP 自有 `/proc` 区间中 runqueue 等待比例为 **24.89%–89.00%**。
  新队列公式的等待比例 MAE 约 **22–24 个百分点**，不是已验证调度模型。
- 相对真实 TP 单位 CPU，旧独立参考 MAPE=2.51%，近邻纯 TP 参考=1.52%；
  说明基线更新之外，还缺 AP 加入后的 TP 服务成本预测。
- 部分 AP task 观察到数十至数百 MB 的写提交，但它不是已核实的
  query-owned spill completion。没有完整算子执行和生命周期 IO 真值，
  不能把这些字节直接叫作 spill 标签。

分步真值替换定位（**离线 CPU 预算情景，不是事前预测精度**）：

| 使用的真实中间量 | 窗口TPS MAPE |
|---|---:|
| 真实 AP 占核，TP 单位成本仍用近邻纯 TP | 2.200% |
| 再给真实 TP 后端单位 CPU | 0.503% |
| 再给真实同机驱动单位 CPU | 0.371% |

所以后续候选继续单独验证“目标之前观测的 AP 占核＋加载后的 TP 单位成本”，
同时必须和朴素的上一窗 TPS persistence 比较，不能把这些真值替换当模型结果。
