# 五阶段饱和 TPS 联合推荐验证

## 验收定义

本轮将“TPS 上下浮动小于 5%”定义为：模型冻结的阶段推荐配置，在相同的
32-terminal 饱和 TP 和固定 AP Query 并发下，其实测 TPS 距已测挑战点中的最高
TPS 不超过 5%。这验证的是配置推荐 regret，不是逐秒 TPS 抖动。

AP 并发固定为 `1/1/2/4/4`，Query 分别为 `Q1`、`Q3`、`Q5+Q7`、
`Q9+Q13+Q18+Q21`、`Q1+Q3+Q5+Q7`。

## 模型升级

1. 新采集一次 `32 terminals + SB=1504MB + work_mem=1024MB` 的五阶段饱和
   锚点轨迹。目标配置的 TPS 没有输入 replay。
2. SB 使用饱和 TP 轨迹重放，不再使用原来 2-terminal、约 40 TPS 的低速轨迹。
3. work_mem 继续使用每 Query 一次锚点、Plan family 和 openGauss 算子源码
   replay，动态内存和 spill 反向作用于 OS cache。
4. 性能优先档把 TP-SB hit 相差不超过 0.001 absolute 的点视为同一饱和平台，
   再按 TP disk I/O、AP spill I/O、动态内存和总内存排序。
5. 所有候选都必须满足实例动态内存约束；S4 停在内存安全边界。

## 公平验证协议

早期 v4 将第二个 profile 运行在第一个 profile 已经暖热的 shared buffer 上，导致
S1 出现 38% 的伪差异。该结果判为无效并保留作诊断，不计入准确率。

最终协议对每个 `(SB, profile)` 独立重启 openGauss、清 Linux page cache，并用
32-terminal TP 预热 90 秒。S2/S3 的短测差异超过 5% 后，又各自执行 120 秒独立
长测；冻结预测没有读取这些验证点。

## 最终结果

| 阶段 | 推荐 SB | 推荐 work_mem | 推荐点 TPS | 最高挑战点 TPS | regret |
|---|---:|---:|---:|---:|---:|
| S1 | 4096MB | 1MB | 1105.90 | 1105.90 | 0.000% |
| S2 | 4096MB | 1150MB | 1207.15 | 1252.96 | 3.657% |
| S3 | 8192MB | 1083MB | 1272.86 | 1333.49 | 4.547% |
| S4 | 8192MB | 2048MB | 1236.88 | 1236.88 | 0.000% |
| S5 | 8192MB | 1150MB | 1323.87 | 1323.87 | 0.000% |

五个阶段全部通过，最大 regret 为 4.547%。S4 的 2048MB 是当前实例动态内存
限制下的可部署边界，仍预测存在 spill，不应表述为全 no-spill 配置。

## 边界

最终比较覆盖模型推荐、统一 1024MB work_mem、4GB/8GB SB，以及 S2/S3 的独立
长测挑战点；它不是所有连续 SB/work_mem 值的穷举证明。结论应表述为“在已测
挑战网格上 5/5 小于 5%”，不能扩展成任意配置或任意新负载的全局最优保证。
